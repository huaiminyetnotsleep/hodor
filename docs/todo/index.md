## 三、执行与验收原则

- 每轮明确「交付 / 不做 / 依赖 / 验收」，每条待办连同相关测试和必要文档一起完成。
- 每个可运行增量完成后再部署验收，不要求每个代码小步骤都 push 到 main。
- 自动化覆盖幂等、并发、过期、重推与部分失败；真实 Telegram 环境验收聊天与部署闭环。
- [功能介绍](/guide/features.md)、[部署流程](/guide/deploy.md)与[原理与架构](/guide/architecture.md)描述的是**已交付的当前行为**；未来能力以本目录（TODO 页）为准，已发布版本的版本历史以 `CHANGELOG.md` 为准。
