# P1

v1 主线：单 bot 双向中继 + 人机验证 + 限频 + 命令全集。方案定稿见[功能介绍](/guide/features.md)与[原理与架构](/guide/architecture.md)。每个里程碑标注本步骤交付的功能；全量清单见 [TODO 总表](/todo/index.md)。

## M0 工程骨架

> 交付：可部署的空 Worker + 数据库就绪 + 测试基座，为后续所有步骤打底。

- [ ] TypeScript + wrangler 工程（无运行时依赖，原生 fetch）
- [ ] wrangler 配置：D1 绑定、keep_vars
- [ ] 六张表 schema 迁移（见[数据表](/guide/database.md)）
- [ ] Git 集成构建：自动创建 D1 数据库并完成绑定（变量名 HODOR_DB，品牌前缀避免与用户自有绑定冲突），免 dashboard 手动操作（需验证构建令牌的 D1 权限，不足时引导用户提供 API token）
- [ ] 部署时自动执行数据库迁移
- [ ] vitest + vitest-pool-workers 测试基座

## M1 Webhook 入口

> 交付：`/webhook` 端点——secret 头校验、update 幂等去重、失败重推与毒丸防护，bot 安全接入的地基。

- [ ] `POST /webhook` 路由与 secret 头校验
- [ ] processed_updates 幂等去重
- [ ] 失败非 200 重推 + MAX_ATTEMPTS 防毒丸

## M2 入站链路（用户 → topic）

> 交付：用户私聊 → 群组 topic 的完整入站链路：建档、欢迎语 + 验证码下发、topic 创建与信息置顶、全类型消息转发、消息落库。

- [ ] 用户建档（首条消息即开始，欢迎语 + 验证码；`/start` 频控；欢迎语文案集中单一模块，便于 fork 改写）
- [ ] topic 确保与创建（名称 = 用户昵称，回退 @username / 用户 ID）+ 用户信息置顶
- [ ] copyMessage 全类型直传 + messages 落库

## M3 出站链路（topic → 用户）

> 交付：群组 topic → 用户私聊的出站链路：管理员身份判定、命令分流入口、thread_id 反查路由、私聊送达。

- [ ] 管理员判定（ADMIN_IDS，非管理员静默忽略）
- [ ] thread_id 反查路由 + 僵尸 topic 提示
- [ ] copyMessage 私聊送达 + 落库

## M4 人机验证与限频

> 交付：人机验证与限频完整能力：数学题 / 纯按钮两种验证码、四种重验触发、TTL 有效期、60 秒窗口限频、提示类回复限频。

- [ ] 数学题验证码（4 答案按钮，正确答案只存库）
- [ ] 纯按钮模式 + /verifymode 切换（settings 表）
- [ ] 四种重验触发：首条 / deluser 后 / 超限 / TTL 过期
- [ ] VERIFY_TTL_HOURS 有效期
- [ ] 60 秒固定窗口限频 + 超限重验（提示文案带限制数字）
- [ ] 提示回复限频（每用户每分钟 1 次）

## M5 命令全集

> 交付：十一个管理命令全部可用：help、ban、unban、risk、unrisk、purgemsg、deluser、note、unnote、verifyon、verifyoff（verifymode 已随 M4 交付）。

- [ ] /help（按验证状态动态展示）
- [ ] /ban /unban
- [ ] /risk /unrisk（置顶标注 + 24 小时一次性提示）
- [ ] /purgemsg（清空 topic + 重置置顶）
- [ ] /deluser（关 topic 留历史 + 重新 start 复用重开）
- [ ] /note /unnote（备注写入 / 清除，展示于置顶信息，随 topic 保留）
- [ ] /verifyon /verifyoff（存量验证保留）

## M6 管理端点

> 交付：setwebhook / deletewebhook 管理端点与 /health 部署自检，形成「部署 → 绑定 → 自检全绿」的收尾闭环。

- [ ] `/setwebhook/<ADMIN_SECRET>`（getMe 回显 bot 身份）
- [ ] `/deletewebhook/<ADMIN_SECRET>`
- [ ] /health 部署自检（环境变量 / 数据库 / webhook 绑定），全过返回 ok + 版本号
