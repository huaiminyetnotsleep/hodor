# 功能介绍

## 核心概念

hodor 把「用户私聊 bot」与「超级群组的话题（topic）」一一映射：**一个人，终身一个 topic**。

```
用户 A ──私聊──▶ Bot ──Webhook──▶ hodor ──转发──▶ 群组 · Topic A
用户 B ──私聊──▶ Bot ──Webhook──▶ hodor ──转发──▶ 群组 · Topic B
用户 A ◀─私聊── Bot ◀──Webhook── hodor ◀─发言── 群组 · Topic A（管理员）
```

- 用户侧：像和普通客服 bot 聊天一样直接发消息
- 管理员侧：在群组中该用户的 topic 里直接说话，消息送达该用户
- 每个用户只能看到自己的消息；管理员可以看到所有对话

## 对话流程

### 用户侧

- 首次给 bot 发消息（**无论是否输入 `/start`**）都会触发：建立用户档案 → 发送欢迎语 → 紧随其后发送验证码
- `/start` 有频控（每用户每分钟最多响应 1 次），防止反复触发欢迎语刷接口；`/start` 本身不转发到客服话题
- 验证通过后，直接发消息即可与客服对话，无需任何命令

欢迎语文案：

> 你好，欢迎使用 hodor 私聊机器人！👋
>
> 直接发送消息即可与客服对话，无需任何命令；客服的回复也会在这里显示。
>
> 项目地址：https://github.com/huaiminyetnotsleep/hodor

文案三要素齐备：**项目名称**（hodor 私聊机器人）、**使用方式**（直接发送消息即可）、**项目地址**。文案集中存放在单一模块中，fork 后可整体改写（含多语言）。欢迎语可通过环境变量 `WELCOME_TEXT` 自定义（支持换行，字面 `\n` 会解释为换行），未配置时使用默认文案。

### 管理员侧

- 只有 `ADMIN_IDS` 中的管理员在 topic 里的发言会被中继给用户，其他群成员发言静默忽略
- 在 topic 里**直接说话即可**，无需回复某条特定消息
- 以 `/` 开头的消息优先按管理命令处理（见下方命令表）

::: tip 查看模式建议
Telegram 超级群组有两种查看方式，客服场景**建议使用话题模式**：

- **话题模式**（推荐）：话题面板就是「收件箱」——有新消息的话题带未读圆点、按活跃度上浮，点开即达对应用户；中继消息在话题内干净呈现，身份即话题标题（用户昵称）
- **消息模式**（整群单条时间线）：所有中继消息都显示为 bot 发送，无法直接分辨来自哪位用户；如需逐条处理用户消息，请切换到话题模式
:::

## 消息能力

- 文本、图片、视频、语音、音乐（音频文件）、文件、贴纸、动图等**全类型消息原样直传**（Telegram file_id 引用，不下载、不落盘、零存储成本）
- topic 名称展示**用户昵称**（`first_name`；缺失时回退 `@username`，再回退用户 ID），建 topic 时确定
- 每个 topic 首次建立时置顶一条用户信息，状态变化时自动更新：

```
昵称：张三（@zhangsan）
用户 ID：123456789
首次聊天：2026-09-29 18:00 (UTC)
验证状态：✅ 已验证
高危标记：⚠️ 高危用户（仅 /risk 后显示）
备注：仅咨询退款（仅 /note 后显示）
```

## 人机验证

防止 bot 刷消息消耗 CF 免费额度。**建议保持开启**（`/verifyoff` 仅在受信任的小范围场景临时使用）。

### 触发场景

| 场景 | 行为 |
| --- | --- |
| 首次发消息 | 建档并发送验证码 |
| `/deluser` 之后 | 清除验证状态，用户重新 `/start` 后重新验证 |
| 分钟限频超限 | 立即标记未验证并发送新验证码 |
| `VERIFY_TTL_HOURS` 过期 | 下一条消息触发重新验证 |

### 验证模式

| 模式 | 说明 | 防护强度 |
| --- | --- | --- |
| 数学题（默认） | `a ± b` 的题目配 4 个答案按钮（1 对 3 错），正确答案只存数据库 | 中 |
| 纯按钮 | 点击单个按钮即通过；bot 可直接调 API「点击」，仅作便利选项 | 低 |
| TGuard（P2 规划中） | 通过 Telegram Mini App 打开第三方验证界面 | 高 |

- 答题错误：编辑原消息提示错误，并自动重新出一题
- 验证未通过期间发送的消息直接丢弃（不积压补发），并按每分钟最多 1 次的频率重发验证码引导

### 有效期与开关

- `VERIFY_TTL_HOURS` 控制有效期，默认 `0` = 永久有效（重验只发生在上方四种场景）
- `/verifyoff` 关闭验证期间**不清除**验证记录；`/verifyon` 重新开启后，此前已验证的用户仍然有效，只有从未验证过的用户需要验证
- 验证开关与模式存数据库（settings 表），命令切换即时生效，无需重新部署

## 频率限制

- `MAX_MESSAGES_PER_MINUTE`（默认 20）：每用户 60 秒固定窗口内最多转发的消息数
- 超限处理：本条丢弃 + 标记未验证 + 发送新验证码，**提示文案带限制数字**（如「发送过快，每分钟最多 20 条，请完成验证后继续」），即触发重新验证，**不是封禁**
- 提示类回复（重发验证码、禁言提示、欢迎语）每用户每分钟最多 1 次，防止对方反过来刷你的请求额度

## 管理命令

全部在对应 topic 内执行，仅 `ADMIN_IDS` 生效：

| 命令 | 作用 | 备注 |
| --- | --- | --- |
| `/help` | 查看命令帮助 | 按当前验证开关状态动态展示对应命令 |
| `/ban` | 禁言该 topic 的用户 | 用户发消息会收到「你已被禁言」提示（限频） |
| `/unban` | 解除禁言 | |
| `/risk` | 标记高危用户 | 正常聊天不受影响；置顶信息加 ⚠️ 标注，并在 topic 内醒目提示一次（24 小时不重复） |
| `/unrisk` | 取消高危标记 | 更新置顶信息 |
| `/purgemsg` | 清空本 topic 的全部消息 | **含管理员发言**；完成后重新置顶用户信息 |
| `/wipealldata` | 一键清空全部数据 | **危险操作**；全局命令，任意 topic 内可执行；删除全部用户与消息记录（settings 保留），两步确认后才执行 |
| `/deluser` | 删除该用户 | 私聊提示用户「请重新 /start」→ 关闭 topic（历史保留）→ 清除验证状态 |
| `/note <内容>` | 添加备注 | 标注该用户 / 对话的用途（如「仅咨询退款」）；写入并更新置顶信息 |
| `/unnote` | 清除备注 | 更新置顶信息 |
| `/verifyon` `/verifyoff` | 开 / 关人机验证 | 两个命令按当前状态展示对应的那个 |
| `/verifymode` | 切换验证模式 | 数学题 ↔ 纯按钮循环切换 |

### /wipealldata 的两步确认

`/wipealldata` 用于一键清空全部数据，因影响全局且不可恢复，执行前强制两步确认：

1. 首次发送 → 回复危险警告并附「确认清理 / 取消」内联按钮
2. 点击「确认清理」后才真正执行；点「取消」或 60 秒超时未确认则放弃，需重新发起

警告文案明确影响范围：**删除全部用户、topic 绑定与消息记录，不可恢复**；settings（验证开关与模式）保留；群组中已创建的 topic 不会被自动删除，旧 topic 内再发言会提示「找不到对应用户」，可手动删除或保留。

### deluser 与 topic 复用

一个人终身一个 topic：`/deluser` 只关闭 topic 并清除该用户的验证与信任状态，**不删除 topic 绑定**。用户重新 `/start` 时会重开原 topic 并重新走验证，管理员在该 topic 里仍能看到这个用户的全部历史；`/note` 写下的备注同样随 topic 保留。想要「干净重开」可以组合使用 `/purgemsg` + `/deluser`。

## 拦截行为汇总

| 用户状态 | 发消息后的行为 |
| --- | --- |
| 未通过验证 | 消息丢弃，每分钟最多重发 1 次验证码 |
| 已被 ban | 消息丢弃，每分钟最多回复 1 次「你已被禁言」 |
| 限频超限 | 本条丢弃，触发重新验证（提示带限制数字） |
